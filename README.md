# PhonePe Banking Decision Intelligence (synthetic data)
All data is synthetic (generated by `generate_data.py`); nothing here reflects PhonePe's real data or is credit advice. Money is in INR.
## How to run
```
pip install -r requirements.txt

```

## Part 1 findings
- **R1.1** H0 (mean spend = INR 8,000) is **rejected**: z_stat = 2.8930, beyond the critical value 1.96. A Type I error here would mean concluding that average spend differs from INR 8,000 when it really equals INR 8,000, so the budget would be revised for no reason. The gap is 8.9382 - 8.0 = 0.9382 units (about INR 938, about 12% of the budget figure; 95% interval 8.3026 to 9.5738). That is likely big enough to matter for budgeting, but spend is very skewed (SD 9.1723), so the mean says little about a typical borrower.
- **R1.2** n_required = 1293 against 800 rows available. The current sample gives a margin of about 1.96 x 0.3243 = 0.64 units, wider than the 0.5 target, so the team would need about 493 more borrowers.
- **R1.3** gd_slope_gap = 0.0000 (below 0.001). The squared-error cost is a single convex bowl, so gradient descent with a modest step converges to the same minimum the closed form solves for directly.
- **R1.4** resid_sd_ratio_raw = 3.7525 and resid_sd_ratio_log = 1.0396. The raw model shows a clear funnel (residual spread grows strongly with the fitted value); the log-log model removes it.
- **R1.5** Predictors with |coefficient| > 0.05: ln(X4) (1.1576), X2 failed transactions (0.0940), X3 utilisation (0.1067) and X6 irregular salary (0.1518). This is a mechanical rule, not an importance ranking. mr_adj_r2 = 0.7403 against loglog_adj_r2 = 0.6561, so the extra predictors earn their place.

## Part 2 findings
- **R2.1** Losses after 200 updates, lowest to highest: eta 1.0 (0.3703), eta 0.1 (0.3776), eta 0.01 (0.5091). A learning rate that is too small is still far from the minimum after 200 steps; a large one converged fastest here, though on harder problems it can overshoot.
- **R2.2** Largest absolute weights: X3 utilisation (0.9013), X1 account age (-0.5554), X2 failed transactions (0.5505). The largest odds ratio is X3 = 2.4629: each one-SD rise in credit utilisation multiplies a borrower's odds of default or 90-days-past-due by about 2.5, other things equal.
- **R2.3** blind_accuracy = 0.7875 against 0.8042 at tau 0.5, so a model that flags nobody is almost as "accurate", and accuracy hides the missed defaults. Lowering tau from 0.5 to 0.3 raised recall from 0.4706 to 0.7451 and lowered precision from 0.5455 to 0.4634.
- **R2.4** Logistic at tau 0.3: f1 0.5714, recall 0.7451. KNN (K = 5): f1 0.3696, recall 0.3333. The logistic model is better on both.
- **R2.5** Deploy the logistic model at tau = 0.15 (cost_tau). Test cost is INR 6,050, against INR 11,800 at tau 0.5 and INR 20,400 for flagging nobody. The threshold was chosen on training rows so the test rows stay an unbiased check; tuning on them would make the test cost optimistic.

## Part 3 findings
- **R3.1** Standardised mean is 0 for every column (about 1e-15 numerically), as the PCA step 1 requires. WCSS drops: 2 to 3 = 659.8282, 3 to 4 = 108.0739, 4 to 5 = 171.0575, 5 to 6 = 45.5466. elbow_k = 3: the 3-to-4 drop is under half of the 2-to-3 drop. The drops do not shrink steadily (4 to 5 is larger than 3 to 4), because the pinned starting rows give a reproducible solution, not necessarily the global optimum.
- **R3.2** Segment A (322 borrowers), "Seasoned steady": about 47.5 months of tenure, 2.0 failed transactions, utilisation 0.225, outcome rate 0.0186; action: low-touch, offer limit increases. Segment B (255), "Heavy active spenders": inflow 28.7k, 6.1 failed transactions, mean spend 17.12, outcome rate 0.2353; action: autopay prompts and a check on failed payments. Segment C (223), "New and stretched": 14.4 months, utilisation 0.7118, repayment score 38.5, **highest outcome rate 0.4664**; action: reminders before the due date and conservative limits.
- **R3.3** Single linkage cuts into 4 clusters: {E1}, {E4}, {E5}, {E2+E3+E6}. Complete linkage cuts into 2 clusters: {E1+E4+E5} and {E2+E3+E6}. Single linkage only looks at the nearest pair, so its merge heights are all small (1.3 to 3.4) and the biggest gap falls early (1.4 to 2.8); complete linkage uses the farthest pair, so the 2.9 to 7.9 jump when the two groups finally join is the dominant gap.
- **R3.4** PC1 contrasts account age (+0.5317) and repayment score (+0.4418) with utilisation (-0.5187), failed transactions (-0.4100) and inflow (-0.2916). Three components are needed to keep at least 80% of variance (cumulative 0.7593 at two, 0.8616 at three). mean_pc1_segment_A/B/C = 1.7773 / -0.7831 / -1.6709, so PC1 orders the segments from stable (A) to stretched (C), the same order as their outcome rates.

## Part 4 findings
- **R4.1** S4 (account age <= 24 months) is best by both measures (info gain 0.1252, Gini gain 0.0606): it separates 188 records with 45.7% positives from 372 with 8.9%. A tree grown until every leaf is pure memorises noise in the training rows and generalises badly. A maximum depth (or a minimum number of records per leaf) stops it.
- **R4.2** I would ship the logistic model at its chosen threshold. At tau 0.3: logistic f1 0.5714 / recall 0.7451; stump 0.5532 / 0.7647; hard vote 0.5344 / 0.6863; soft vote 0.5507 / 0.7451; KNN 0.3696 / 0.3333. Combining did not help over the best single model.
- **R4.3** After round 1 the two misclassified points (3 and 7) carry a total weight of 0.5000. Round 2 trusts h2 more because its weighted error (0.1667) is lower than h1's was (0.2500), giving alpha 0.8047 against 0.5493.

## Model-choice memo
To: Head of Lending-Risk. Recommendation: ship the logistic-regression model (seven standardised predictors) for collections nudges, flagging borrowers whose default probability is at least 0.15.

Why this threshold: it minimised cost on the training rows (INR 12,150), with a false alarm costing INR 50 and a missed default INR 400. On the 240 held-out rows it costs INR 6,050, against INR 11,800 at the default 0.5 cut-off and INR 20,400 if nobody is flagged. At 0.3 the model reaches recall 0.7451 and F1 0.5714, ahead of K-nearest neighbours (F1 0.3696, recall 0.3333). A one-question stump and the two voting ensembles came close on F1 (0.5532, 0.5344, 0.5507) but did not beat the logistic model, so combining models added complexity without gain. I did not compute their INR costs with the cost rule, so no cost is quoted for them.

Limitation: the data is synthetic, and the test set holds only 51 defaults, so one split gives a noisy cost estimate; the 0.15 threshold is valid for this split only and must be re-checked on real, recent repayment data before use.

Model A or B: neither is worth building before the structured model is in production, because neither feeds the default score; if one goes first it should be Model A, a small convolutional digit reader of about 15,734 parameters.

## Limitations
- The data is synthetic, so the patterns (and the 80/20 default rate) are generator-made and may not carry over to real borrowers.
- One fixed 70/30 split with only 51 positive test records: the K, the threshold and all test costs are valid for this split only and are noisy.
- The INR cost rule (50 per false alarm, 400 per miss) is a rough planning figure; real costs vary by borrower and loan size.
- K-means uses pinned starting rows and may not reach the global optimum; the hierarchical table is a supplied toy example.
- Only the logistic model's INR cost was computed; the other models were compared on F1 and recall alone.
